acme-txt - ACME DNS-01 challenge TXT records for certbot
========================================================

SYNOPSIS
--------
  acme-txt [OPTIONS] --server=<server> --zone=<zone> add <fqdn> <value>
  acme-txt [OPTIONS] --server=<server> --zone=<zone> del <fqdn> <value>
  acme-txt [OPTIONS] --server=<server> --zone=<zone> --ssh

DESCRIPTION
-----------
acme-txt adds and deletes the TXT records that an ACME CA (Let's Encrypt)
checks when it issues a certificate with the DNS-01 method:

  _acme-challenge.<CERTBOT_DOMAIN>  TXT  "<CERTBOT_VALIDATION>"

It is meant to be run as an SSH forced command, so that a user or a host
can renew its certificates from certbot hooks without access to the web UI
and limited to _acme-challenge TXT records in its own zone(s). It is a
stop-gap until Sauron has an API.

Rules:
  * <fqdn> must be _acme-challenge or _acme-challenge.<name> inside one of
    the zones given with --zone (the longest matching zone is used).
  * <value> must look like CERTBOT_VALIDATION (43 characters, base64url).
  * Only TXT hosts (type 13) are created, changed or deleted. A name used
    by another host type (e.g. a CNAME delegating _acme-challenge
    elsewhere) is refused.
  * 'add' of a value that already exists and 'del' of a value or name that
    does not exist succeed and change nothing, so certbot can retry.

Several values for one name are supported. A certificate for example.cz
and *.example.cz needs two different values of _acme-challenge.example.cz
at the same time: the first value is stored like any TXT host in the web
UI (hosts.cname_txt), further values in txt_entries of the same host. Both
are written to the zone. 'del' removes one value; the host is deleted with
its last value.

Note: saving such a host in the web UI keeps only its first value.

A new record gets a short TTL (--ttl) and an expiration (--expire), so a
record that certbot failed to clean up stops being published and is
removed later by 'sauron --clean'.

Changes are recorded in the host history (action 'ACME: add TXT' /
'ACME: delete TXT') with the user name; hosts.cuser/muser is
'acme-txt:<user>'.

The record is published when the zone is next generated by 'sauron'
(usually check-pending run from cron). acme-txt does not regenerate the
zone; the certbot auth hook has to wait until the authoritative name
servers answer with the value (see contrib/certbot-sauron-hook.sh).

OPTIONS
-------
  --server=<name>   Sauron server the zone belongs to (required).
  --zone=<zone>     Zone the caller may modify (required, repeatable).
  --ssh             Read the request "add|del <fqdn> <value>" from
                    SSH_ORIGINAL_COMMAND; no other arguments are accepted.
  --ttl=<sec>       TTL of a new record (default 60, 0 = zone default).
  --expire=<sec>    Expiration of a new record in seconds from now
                    (default 86400, 0 = never). Adding a value to a record
                    that has an expiration moves it forward.
  --user=<name>     User name for the history (default: login name).
  --verbose         Print the zone and the relative name used.
  --help            Show usage.

EXIT STATUS
-----------
  0  done (or nothing to do)
  1  usage error
  2  request refused (name, value, zone, server or host type)
  3  database error

SETUP
-----
1. On the Sauron host create an account for the requests, able to read
   the Sauron configuration (it contains the database password), e.g.:

     useradd -m -s /bin/sh sauron-acme
     # give it read access to /usr/local/etc/sauron/config, e.g. by group

2. Add one line per client key to ~sauron-acme/.ssh/authorized_keys. The
   server and zone(s) come only from the forced command, the client cannot
   change them:

     restrict,command="/usr/local/sauron/acme-txt --server=cesnet --zone=example.cz --user=www-example --ssh" ssh-ed25519 AAAA... certbot@www.example.cz

3. On the client install contrib/certbot-sauron-hook.sh and set
   SAURON_SSH=sauron-acme@sauron.example.net (in the environment or in
   /etc/default/certbot-sauron-hook).

EXAMPLES
--------
Request a certificate for the apex and a wildcard:

  certbot certonly --manual --preferred-challenges dns \
    --manual-auth-hook    "/usr/local/bin/certbot-sauron-hook.sh auth" \
    --manual-cleanup-hook "/usr/local/bin/certbot-sauron-hook.sh cleanup" \
    -d example.cz -d '*.example.cz'

What the hook sends over SSH:

  ssh sauron-acme@sauron "add _acme-challenge.example.cz <value>"
  ssh sauron-acme@sauron "del _acme-challenge.example.cz <value>"

Local use on the Sauron host:

  acme-txt --server=cesnet --zone=example.cz \
    add _acme-challenge.www.example.cz <value>

TROUBLESHOOTING
---------------
  * "refused: ... is not _acme-challenge.<name> in an allowed zone":
    the name is outside the zones in the forced command.
  * "refused: ... exists and is not a TXT record": the name is used by
    another host, e.g. a CNAME. Remove it or keep using that delegation.
  * The auth hook times out: check that the export job runs (status
    --pending=<server>) and raise SAURON_WAIT above its interval.
