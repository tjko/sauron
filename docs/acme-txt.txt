acme-txt - ACME DNS-01 challenge TXT records for certbot
========================================================

SYNOPSIS
--------
  acme-txt [OPTIONS] --server=<server> --zone=<zone> add <fqdn> <value>
  acme-txt [OPTIONS] --server=<server> --zone=<zone> del <fqdn> <value>
  acme-txt [OPTIONS] --server=<server> --zone=<zone> --ssh
  acme-txt [OPTIONS] --server=<server> --cleanup

DESCRIPTION
-----------
acme-txt adds and deletes the TXT records that an ACME CA (Let's Encrypt)
checks when it issues a certificate with the DNS-01 method:

  _acme-challenge.<CERTBOT_DOMAIN>  TXT  "<CERTBOT_VALIDATION>"

It is meant to be run as an SSH forced command, so that a user or a host
can renew its certificates from certbot hooks without access to the web UI
and limited to _acme-challenge TXT records in its own zone(s). It is a
stop-gap until Sauron has an API.

Rules:
  * <fqdn> must be _acme-challenge or _acme-challenge.<name> inside one of
    the zones given with --zone (the longest matching zone is used),
    with labels of at most 63 and a name of at most 253 characters.
  * <value> must look like CERTBOT_VALIDATION (43 characters, base64url).
  * Only TXT hosts (type 13) created by acme-txt with the same --user
    (hosts.cuser 'acme-txt:<user>') are changed or deleted, so give each
    client key its own --user. A name used by another host type (e.g. a
    CNAME delegating _acme-challenge elsewhere), by a TXT host created in
    the web UI or by another --user is refused (names are compared
    without regard to case).
  * A name at or below a delegation (NS) in the zone is refused: 'sauron'
    leaves such records out of the zone.
  * At most 10 values per name.
  * 'add' of a value that already exists and 'del' of a value or name that
    does not exist succeed and change nothing, so certbot can retry.
  * Requests for the same name are serialized (PostgreSQL advisory lock),
    so concurrent hooks cannot exceed the limit or lose a value.
  * Deleting the last value deletes only the TXT record; aliases that
    point to the name (e.g. a CNAME delegating another name's challenge
    here) are kept. Aliases that reference the host itself are turned into
    static aliases of the name, so they work again after the next 'add'.

Several values for one name are supported. A certificate for example.cz
and *.example.cz needs two different values of _acme-challenge.example.cz
at the same time: the first value is stored like any TXT host in the web
UI (hosts.cname_txt), further values in txt_entries of the same host. Both
are written to the zone. 'del' removes one value; the host is deleted with
its last value.

Note: saving such a host in the web UI keeps only its first value.

A new record gets a short TTL (--ttl) and an expiration (--expire), so a
record that certbot failed to clean up does not stay in DNS. 'sauron' does
not notice an expiration by itself (the zone is not marked as changed), so
run 'acme-txt --server=<server> --cleanup' from cron before check-pending:
it deletes expired records created by acme-txt in all zones of the server
and the next export publishes the zone without them. Every 'add' sets the
expiration again from now (--expire=0 removes it) and marks the zone as
changed, so a record left out of the zone after it expired is published
again.

Changes are recorded in the host history (action 'ACME: add TXT' /
'ACME: delete TXT') with the user name, in the same transaction as the
change where possible; hosts.cuser/muser is 'acme-txt:<user>'. If the
history cannot be written, acme-txt exits with status 3.

The record is published when the zone is next generated by 'sauron'
(usually check-pending run from cron). acme-txt does not regenerate the
zone; the certbot auth hook has to wait until the authoritative name
servers answer with the value (see contrib/certbot-sauron-hook.sh).

OPTIONS
-------
  --server=<name>   Sauron server the zone belongs to (required).
  --zone=<zone>     Zone the caller may modify (required, repeatable).
  --ssh             Read the request "add|del <fqdn> <value>" from
                    SSH_ORIGINAL_COMMAND; no other arguments are accepted.
  --cleanup         Delete expired records created by acme-txt in all
                    zones of --server (from cron; not with --zone/--ssh).
  --ttl=<sec>       TTL of a new record (default 60, 0 = zone default).
  --expire=<sec>    Expiration of a new record in seconds from now
                    (default 86400, 0 = never). Every 'add' sets the
                    expiration of the record again.
  --user=<name>     User name for the history (default: login name).
  --verbose         Print the zone and the relative name used, or the
                    records deleted by --cleanup.
  --help            Show usage.

EXIT STATUS
-----------
  0  done (or nothing to do)
  1  usage error
  2  request refused (name, value, zone, server, host type, owner or
     delegation)
  3  database error

SETUP
-----
On the Sauron host (as root):

1. Install Sauron with acme-txt (make install -> /usr/local/sauron/acme-txt).

2. Create an account for the requests. It needs a real shell (sshd runs
   the forced command with "$SHELL -c"), no password, and read access to
   the Sauron configuration (it contains the database password; the file
   must not be group or world writable):

     useradd --system --create-home --home-dir /var/lib/sauron-acme \
             --shell /bin/sh sauron-acme
     passwd -l sauron-acme

   A locked password does not prevent key login with UsePAM yes (Debian
   default). Without PAM OpenSSH refuses locked accounts; then set the
   password field to '*' instead (usermod -p '*' sauron-acme).

3. Make ~/.ssh and authorized_keys owned by root, so the account cannot
   change them:

     install -d -o root -g root -m 755 /var/lib/sauron-acme/.ssh
     install -o root -g root -m 644 /dev/null \
             /var/lib/sauron-acme/.ssh/authorized_keys

4. Add one line per client key. The server and zone(s) come only from
   the forced command; the client's command line is only read from
   SSH_ORIGINAL_COMMAND as "add|del <fqdn> <value>". 'restrict' disables
   PTY, port/agent/X11 forwarding and ~/.ssh/rc; from= limits the source
   address; use several --zone options for more zones:

     restrict,from="192.0.2.10,2001:db8::10",command="/usr/local/sauron/acme-txt --server=cesnet --zone=example.cz --user=www-example --ssh" ssh-ed25519 AAAA... certbot@www.example.cz

   Keep PermitUserEnvironment no and do not accept PERL* variables with
   AcceptEnv in sshd_config, otherwise the client could change how perl
   runs acme-txt (check with: sshd -T | grep -i -e acceptenv -e userenv).

5. Delete expired records from cron, before the export job, e.g. in
   /etc/cron.d/sauron-acme:

     */10 * * * * root /usr/local/sauron/acme-txt --server=cesnet --cleanup

On the client (as root, certbot runs hooks as root):

6. Create a key and send the public part to the Sauron admin:

     ssh-keygen -t ed25519 -N '' -C certbot@www.example.cz \
                -f /etc/letsencrypt/sauron-acme

7. Add the Sauron host key to known_hosts (the hook uses BatchMode and
   fails on an unknown host key); check the fingerprint:

     ssh-keyscan sauron.example.net >> /root/.ssh/known_hosts

8. Install contrib/certbot-sauron-hook.sh as
   /usr/local/bin/certbot-sauron-hook.sh and create
   /etc/default/certbot-sauron-hook:

     SAURON_SSH=sauron-acme@sauron.example.net
     SAURON_SSH_KEY=/etc/letsencrypt/sauron-acme
     SAURON_WAIT=1800     # longer than the interval of the export job

9. Test it (each command prints the exit status):

     K="-i /etc/letsencrypt/sauron-acme sauron-acme@sauron.example.net"
     V=$(head -c32 /dev/urandom | base64 | tr '+/' '-_' | tr -d =)
     ssh $K "add _acme-challenge.example.cz $V"; echo $?      # 0
     ssh $K "del _acme-challenge.example.cz $V"; echo $?      # 0
     ssh $K "add _acme-challenge.example.com $V"; echo $?     # 2
     ssh $K "add _acme-challenge.example.cz $V; id"; echo $?  # 1
     ssh -t $K; sftp $K; ssh -N -L 5432:localhost:5432 $K     # all fail

EXAMPLES
--------
Request a certificate for the apex and a wildcard:

  certbot certonly --manual --preferred-challenges dns \
    --manual-auth-hook    "/usr/local/bin/certbot-sauron-hook.sh auth" \
    --manual-cleanup-hook "/usr/local/bin/certbot-sauron-hook.sh cleanup" \
    -d example.cz -d '*.example.cz'

What the hook sends over SSH:

  ssh sauron-acme@sauron "add _acme-challenge.example.cz <value>"
  ssh sauron-acme@sauron "del _acme-challenge.example.cz <value>"

Local use on the Sauron host:

  acme-txt --server=cesnet --zone=example.cz \
    add _acme-challenge.www.example.cz <value>

TROUBLESHOOTING
---------------
  * "refused: ... is not _acme-challenge.<name> in an allowed zone":
    the name is outside the zones in the forced command.
  * "refused: ... exists and is not a TXT record": the name is used by
    another host, e.g. a CNAME. Remove it or keep using that delegation.
  * The auth hook times out: check that the export job runs (status
    --pending=<server>) and raise SAURON_WAIT above its interval.
